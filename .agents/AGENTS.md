# Workspace Agent Rules

## 1. 專案整體程式碼與檔案優化作業觸發協定 (Codebase Cleanup & Optimization Protocol)
當用戶輸入觸發咒語：「**執行專案的整體程式碼與檔案優化作業**」時，必須立刻自動調用 `codebase-cleanup-optimization` Skill 並嚴格執行以下 5 大閉環 SOP：

1. **全面盤點與清理作業**：遍歷專案所有目錄與檔案，識別並移除過時、冗餘、無效的程式碼片段與獨立檔案（含棄用模組、未引用資源檔、重複邏輯及失效配置），過程確保現有功能正常運作。
2. **同步更新所有開發相關文件**：全面檢視 `DEV_LOG.md`、專案 Wiki 等所有開發文件，同步更新至最新功能狀態，補充新增功能說明、調整架構描述、更新版本記錄、修正過時操作指引，確保文件與程式碼完全一致。
3. **遵循 MECE 原則整合整理**：以相互獨立、完全窮盡 (MECE) 的分類邏輯整合剩餘有效資源，統一檔案存放結構與程式碼格式，梳理模組間依賴關係，消除分類模糊或重疊配置。
4. **建立程式碼還原基準點**：透過 Git 提交本次所有變更，編寫清晰規範的 Commit 訊息，說明清理、更新與整合的具體內容，建立可追溯、可還原的版本基準。
5. **推送變更至 GitHub 遠端倉庫**：確認無數據隱私與敏感資訊問題且本地提交無誤後，將變更推送至 GitHub 對應分支，完成部署流程。

## 2. 國際標準 (SSOT) 零捏造與技術參數溯源防禦協定 (Zero-Hallucination & SSOT Traceability Protocol)
在編寫、改寫或通俗化 ISO/IEC 醫療器材標準（如 ISO 80369 系列）相關文案、規格說明與投影片內容時，必須強制遵守以下防禦規範：
1. **零腦補與零捏造 (Zero Fabrication)**：
   - 絕對禁止為追求通俗生動而憑空發明不存在的試驗步驟或臨床情境（例如將 ISO 80369-7 條文 6.3 常溫常濕乾燥組裝耐應力龜裂試驗，腦補為「泡在藥水/酒精裡兩天兩夜」）。
   - 通俗比喻（如「考駕照」、「西瓜吊掛」）僅限於生活化對照，表格本體與條文說明必須精準還原標準物理條件。
2. **參數與條文精確溯源 (Parameter Traceability)**：
   - 區分「前置裝配 SOP（ISO 80369-20 附錄 D/F/G/H：26.5~27.5 N + 0.08~0.12 N·m，持載 5~6 秒）」與「後續測試持壓時間（6.1.3 正壓液體落滴 30~35 秒；6.1.2 氣壓衰減 15~20 秒；6.2 負壓抽吸 15~20 秒）」，絕對禁止混為一談。
   - 力學試驗數值（滑套 23~25 N、帶鎖 32~35 N）必須完整呈現公差區間，拒絕過度四捨五入導致法規不合規。
   - 涉及跨標準驗證時（如防呆互斥），必須明確區分引用層級（ISO 80369-1 附錄 B 測試方法 vs ISO 80369-7 條文 5 / 附錄 A 判定原則）。

## 3. 產品標準 (Part 7) 與方法標準 (Part 20) 嚴格解耦與防拼貼協定 (Product Spec vs Test Method Strict Decoupling Protocol)
針對醫療器材小口徑連接器標準體系，為防止「知識拼貼偏誤」與「法規認知混亂」，必須強制遵守以下防禦規範：
1. **裁判 (Product Spec) 與工具 (Test Method) 嚴格解耦**：
   - **母標準 (ISO 80369-7)** 是「裁判」：唯一負責定義法定允收標準 (Statutory Pass/Fail Criteria)、特定產品工況載荷，以及指派法定驗收條文。
   - **通用方法 (ISO 80369-20)** 是「工具箱」：僅負責儀器架構、感測器精度、溫濕度預調理與操作步驟。它本身不宣告產品合格，必須將數據交回母標準裁定。
   - **嚴禁拼貼擴充**：絕對禁止在母標準卡片或 SOP 中，擅自拼貼未經母標準條文授權的替代驗收途徑（例如在 §6.3 應力龜裂中自作聰明加入「或 6.2 負壓」）。
2. **第一性原理物理機制檢驗 (First-Principles Physics Verification)**：
   - 任何驗收邏輯必須通過固體力學與流體力學的客觀真實驗證。
   - 範例：環向拉伸預緊應力導致之微裂隙（Mode I Crack Opening），在負壓（真空）由外向內的壓差作用下會被擠壓閉合（Crack Closure Effect），導致負壓無法測出漏氣；因此標準唯一指定 300~330 kPa 正壓將裂紋撐開促成洩漏。
3. **法定判據與工程紀錄嚴格分流 (Statutory Criteria vs Engineering Record)**：
   - **法定允收標準**：法規唯認客觀可量測之物理結果（如通過 6.1.1 正壓流體洩漏、未發生完全軸向分離）。
   - **工程觀察項目**：實驗室目視顯微鏡檢查（如銀紋、微裂痕）僅屬於 Annex E.5(h) 之試驗報告記載事項，不得將其作為唯一的法規法定判定門檻。
4. **接頭全型別與公差區間完整覆蓋 (Full Typology & Tolerance Coverage)**：
   - 嚴禁以偏概全：涉及接頭型別時，必須同時並列「鎖定型 (Lock)」與「滑動型 (Slip)」之差異化載荷（如預裝配：鎖定型 0.08~0.12 N·m vs 滑動型軸向推力微旋 ≤90°；拉力測試：鎖定型 32~35 N vs 滑動型 23~25 N），公差區間必須完整呈現。
